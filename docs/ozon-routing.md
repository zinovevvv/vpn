# Ozon: DIRECT и проверка приложения

Дата исследования: 2026-09-14. Основа: `origin/main`, commit `35e084b`.

## Вывод

Главные домены Ozon уже были в DIRECT. `domain:ozon.ru` в HAPP/Xray и
`domain_suffix` / `DOMAIN-SUFFIX` в других конфигах покрывают сам домен и
все уровни поддоменов. Отдельные записи для `api.ozon.ru`, `xapi.ozon.ru`,
`id.ozon.ru`, `ir.ozone.ru`, `cdn1.ozonusercontent.com` не нужны.
Это распространяется на TCP и UDP, когда клиент знает домен назначения.

Добавлены девять отсутствовавших зон: `ozonru.me`, `ozon.by`, `ozon.kz`,
`ozon.com.by`, `ozon.com.kz`, `ozon.uz`, `ozon.tm`, `ozon.global`, `ozon.travel`.
Это расширение покрытия, а не доказательство причины конкретного сбоя приложения.
Гарантия для всех версий приложения требует проверки его реального трафика.

## Исследование несколькими способами

1. Проверены текущие конфиги и порядок правил. Базовые API/CDN уже покрыты.
2. Проверен [список v2fly](https://github.com/v2fly/domain-list-community/blob/master/data/ozon)
   как источник кандидатов. Он не импортирован целиком: `ozon.app` на дату
   проверки имеет NS `ns1.afternic.com` / `ns2.afternic.com`, поэтому не добавлен.
3. Для всех девяти добавленных зон проверены NS через Google DNS over HTTPS:
   `https://dns.google/resolve?name=ozonru.me&type=NS` (заменить имя для других зон).
   У всех NS находятся под `ozon.ru` / `ozon.com`. Это подтверждает связь с
   инфраструктурой Ozon, но не доказывает использование каждой зоны приложением.
4. Открыта [главная страница Ozon](https://www.ozon.ru/) в браузере на Mac:
   после автоматической antibot-проверки появились товары и загрузились изображения.
   Из DOM извлечены домены ресурсов: `cdn1.ozonusercontent.com`, `io.ozone.ru`,
   `ir.ozone.ru`, `st.ozone.ru`, `v-1.ozone.ru`, `vp-1.ozone.ru`, `vr-1.ozone.ru`,
   `vt-1.ozone.ru`, `p.ozon.ru`. Все покрыты корневыми правилами.
   Сама страница ссылается на `ozon.by`, `ozon.kz`, `www.ozon.uz`.
   DOM не является полным перечнем фоновых запросов или трафика приложения.
5. Проверены HTTPS-запросы через физический Wi-Fi `en0` командой
   `curl --noproxy '*' --interface en0 ...`, без отключения VPN и изменения
   системных маршрутов. TLS проверялся штатно.

| Проверка через en0 | HTTP | Что подтверждено |
| --- | --- | --- |
| Логотип на `ir.ozone.ru` | 200 | Ресурс доступен через Wi-Fi |
| Изображение товара на `cdn1.ozonusercontent.com` | 200 | CDN доступен через Wi-Fi |
| `www.ozon.ru/` | 307 | Сервер отвечает, требуется обработка редиректа/cookie |
| `api.ozon.ru/` | 307 | HTTPS доступен, работа методов API не проверена |
| `xapi.ozon.ru/` | 418 | Ответ сервера, не успешный запрос приложения |
| `ozonru.me/` | 403 | Ответ сервера, не успешная загрузка приложения |

Обычный `curl --noproxy '*'` сам по себе не обходит TUN VPN. В этой сессии
системный маршрут к одному из IP Ozon шёл через `utun9`; поэтому отдельно
использована привязка сокета к физическому `en0`. Это проверка транспорта
Mac, а не подтверждение выбора DIRECT установленным HAPP.
Обычный UDP DNS через `dig` завершался тайм-аутом; NS проверены через DoH.

## Границы изменений

- Не добавлены общие сети Cloudflare, Google, Apple и новые широкие CDN-исключения.
- Не добавлен `keyword:ozon`: он захватил бы посторонние домены с такой строкой.
- Существующие `ozoncdn.com` и `ngenix.net` сохранены, но их необходимость для
  текущего приложения не доказана. Корень `ozoncdn.com` в проверке не разрешился.
- Прямые запросы к IP без доступного домена зависят от IP-правил и sniffing клиента.
  DNS cache, собственный DoH приложения, QUIC и ECH могут осложнять диагностику.
- Изменения файлов репозитория не меняют автоматически активный профиль телефона.
  Нужно импортировать новый профиль, выбрать его у подписки и переподключиться.
  У Hiddify остаётся описанное в AGENTS.md ограничение импорта routing-only файла.

## Как проверить мобильное приложение с Mac

Лучший тест — реальный телефон с тем же VPN-клиентом и новым профилем.
Повторить сначала без VPN, затем с VPN: холодный запуск Ozon, поиск, карточка
товара, фото/видео, корзина, экран авторизации. Оформлять заказ или платить для
проверки не требуется. Для каждого сценария проверить журнал соединений VPN:
домены Ozon должны иметь выход DIRECT/freedom. Название выхода зависит от клиента.
Если трафик идёт DIRECT, но экран не работает, нужно исследовать DNS, ответы
сервера и доступность провайдера, а не добавлять домены наугад.

### iPhone + USB

[Apple описывает запись трафика через RVI](https://developer.apple.com/documentation/network/recording-a-packet-trace).
Нужны Xcode и подключённый по USB iPhone с установленным доверием к Mac.
На исследованном Mac Xcode и rvictl не найдены, поэтому захват не выполнялся.
После подготовки окружения:

```sh
rvictl -s <UDID_телефона>
sudo tcpdump -i rvi0 -n -w /tmp/ozon-iphone.pcap
# Воспроизвести сценарий, остановить tcpdump через Ctrl+C.
rvictl -x <UDID_телефона>
```

Использовать имя интерфейса, реально выданное rvictl. В Wireshark смотреть
DNS и TLS SNI, когда они видны, и сопоставлять время/IP с журналом клиента.
Шифрованный DNS/ECH и VPN-туннель могут скрыть домены: pcap один не гарантирует
полный список и не заменяет журнал маршрутизации. Захват может включать трафик
других приложений; хранить его локально, не коммитить в публичный репозиторий.

### Android

Можно проверить на реальном Android через журнал VPN-клиента. Без телефона
доступен [Android Emulator на Mac](https://developer.android.com/studio/run/emulator-commandline):
установить официальное приложение Ozon из поддерживаемого магазина и тот же VPN-клиент,
выбрать этот routing и повторить сценарии. Android Studio/SDK на исследованном Mac
не найдены; эмулятор не запускался. Он проверит только Android-сборку и не заменяет iPhone.

## Документация форматов и применения

- [Xray routing](https://xtls.github.io/config/routing.html): `domain:` охватывает поддомены;
  правила применяются по порядку, IPIfNonMatch сначала проверяет доменные правила.
- [sing-box route rules](https://sing-box.sagernet.org/configuration/route/rule/).
- [HAPP routing](https://www.happ.su/main/dev-docs/routing): профиль привязан к подписке,
  применение требует reconnect; одинаковое имя обновляет существующий профиль.
  Для нового имени `Neplach routing 2609-ozon` нужно проверить выбор нового профиля.
  У готовых JSON-подписок возможности импорта ограничены поставщиком.
